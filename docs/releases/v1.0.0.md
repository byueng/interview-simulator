# Interview Simulator v1.0.0

发布日期：2026-09-06  
状态：功能冻结，作为 Web 迁移前的终端版基线。

## 定位

面向技术岗位的本地中文 AI 模拟面试程序。用户从 Markdown 题库选择题目、作答后获得模型驱动的追问或最终评分，并将练习记录保存到本地 SQLite。当前已提供 Agent 工程师赛道。

## 已实现

- Markdown 题库扫描：读取题号、模块、难度、题目和参考解析；题库路径及每页题数由 `config.json` 配置。
- Textual 终端选题界面：按页浏览题目，展示模块、难度、是否练习和最近得分；支持进入单题评分或深入面试。
- 面试编排：单题评分在首轮作答后结束；深入面试最多 10 轮，候选人明确回答“我不知道”等无法作答语句时结束。
- OpenAI-compatible Chat Completions 模型接入：模型配置从 `.env` 读取，不写入仓库；温度当前由 `config.json` 配置为 `0.9`。
- 流式体验：模型 SSE 输出经本地 FastAPI 服务转发给 TUI，追问和评价可增量显示。
- 数据一致性：模型流式文本完整解析并通过 JSON 字段校验后，才持久化本轮回答、追问或最终评分，避免断流写入半成品。
- 本地数据：SQLite 保存会话、轮次、最终评价及题目练习进度。
- 日志：记录本机服务和模型调用结果，日志配置会脱敏模型 API Key。
- 中文内容展示与粘贴：题目、反馈、回答和评价可以显示中文，回答框可粘贴中文。
- 兼容输入入口：面试页提供普通终端作答按钮和 F2 快捷键；它会临时挂起 Textual，通过普通终端 `input()` 采集回答后回填。

## 已知缺点与边界

1. **直接中文输入体验不可用**：在当前 macOS + iTerm2 + Textual `TextArea` 组合中，拼音预编辑和候选词不会出现；这不是 Unicode 渲染问题，因为中文粘贴可正常显示。普通终端输入入口是临时绕过，不是理想交互。
2. **终端作答需切换界面**：普通终端输入使用户暂时离开 TUI，回车后再回填，交互割裂。
3. **真实模型尚未端到端验收**：自动化测试没有调用用户实际配置的模型服务，不能据此声称真实供应商、JSON 格式或真实 SSE 已联通。
4. **评分风格配置未生效**：`config.json` 中存在 `scoring.feedback_style`，但当前运行时只把 `temperature` 传入模型客户端；评分风格尚未进入系统提示词。
5. **评分存在模型不确定性**：即使设定了 `temperature=0.9` 和严格提示词，评分与措辞仍取决于模型输出；没有独立的评测集、基准答案评分器或人工校准机制。
6. **上下文管理基础**：每轮将完整会话记录传给模型；仅以 10 轮上限控制长度，尚未做 token 预算、摘要压缩或长会话恢复。
7. **本地单用户定位**：SQLite 与临时本机 FastAPI 端口适合个人练习；没有账户、权限、并发控制、远程部署、任务取消或会话恢复机制。
8. **展示能力有限**：面试记录使用 `Static` 逐步刷新，长文本滚动、复制、复杂排版和移动端体验均不理想。

## v2.0：Web 端迁移方向（规划，未实现）

目标是保留题库、面试编排、评分、SSE 和 SQLite 的领域逻辑，将作答和展示迁移到浏览器原生输入框，解决中英文 IME、长文本和历史记录浏览问题。

建议优先顺序：

1. 抽清 API 契约：保留并补全题目、会话、提交回答、SSE 流和历史查询接口；让 Web 客户端只依赖 HTTP/SSE，不依赖 Textual。
2. 构建最小 Web 面试页：题目列表、模块/难度/练习状态、题目详情、原生多行作答框、流式面试记录和最终评分。
3. 处理前端状态：提交期间禁用重复提交、流中断可见、会话恢复、页面刷新后恢复进行中的面试。
4. 再迭代评分可配置化：让 `feedback_style` 真实参与系统提示词，并通过固定样例回归测试“严格但基于证据”的评价风格。
5. 最后评估数据层升级：个人本地使用可继续 SQLite；多用户或部署后再迁移到 PostgreSQL，并加入认证、会话隔离和观测能力。

## 迁移原则

- 不重写已验证的题库解析、面试状态编排、JSON 校验和 SQLite 数据模型。
- Web 端先替换表现层；领域服务和 API 契约稳定后，再考虑部署和多用户能力。
- v2.0 的任何真实模型、浏览器 SSE 和中文 IME 结论，都必须在目标环境手工验收后才标记为已实现。
