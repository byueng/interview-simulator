# Interview Simulator v1.1.0

发布日期：2026-09-16  
状态：本地 Web 表现层增量，未宣称为远程部署或多用户版本。

## 本次已实现

- 新增 `uv run interview-simulator --web`：启动后在 `127.0.0.1` 提供浏览器面试页。页面复用已有 FastAPI、SSE、`InterviewService` 和 SQLite，不复制或重写题库解析、状态编排与持久化逻辑。
- Web 页提供题库选择、单题评分/深入面试选择、原生多行作答框、流式反馈、最终评价和已练习/最近分数展示。
- 会话 API 返回 `current_question`，让任意 HTTP 客户端能恢复当前待答问题；这是向前兼容的响应字段扩展。
- `scoring.feedback_style` 不再是无效配置：支持 `detailed_interviewer` 和 `pressure_interviewer` 两个固定预设，并同时注入追问、流式追问、最终评价和流式评价的系统提示词。
- 高压预设只要求面试官追问证据、工程边界和取舍，明确禁止羞辱、人身攻击或虚构候选人说过的话。

## 已验证范围

- 配置校验覆盖不支持的评分风格。
- 模型客户端单测断言高压预设确实进入系统提示词并包含行为边界。
- API 单测覆盖 Web 根页面与静态脚本可被本地 FastAPI 提供。
- 其余既有服务、SSE、存储和终端用例会在 v1.1 修改后整体回归运行。

## 仍未完成或需人工验收

1. 未调用实际模型供应商；`httpx.MockTransport` 只能证明请求/响应契约与 JSON 校验，不证明真实模型的 JSON 服从性或真实 SSE 连通性。
2. 浏览器原生输入框是为中文 IME 选择的表现层替代，尚未在本机目标浏览器进行人工输入验收，不能据此说 Textual IME 已修复。
3. 页面刷新后尚未自动恢复进行中的会话，SSE 中断也只展示错误提示，不支持续流或取消请求。
4. 本地服务仍是单用户、loopback 绑定；没有认证、权限、并发控制、远程部署、数据库迁移或可观测平台。
5. 两种评分风格已进入提示词，但尚未建立固定样例集或人工评分基准来校准稳定性与公平性。

## 面试表述边界

可以如实表述为：在本地技术面试模拟工具中，将 Textual 与浏览器前端通过统一 FastAPI/SSE 契约接入同一领域服务，并为模型面试官实现受限、可配置的反馈风格；流式文本经过结构化 JSON 校验后才落库。

不能表述为：已完成生产级多用户部署、真实模型供应商端到端验收，或已彻底修复 Textual 在 macOS 终端中的中文 IME 问题。
